# AI地域商社（MVP）

飲食店が自然文で書いた仕入れの希望と、複数の生産者が登録した在庫を照らし合わせて、
「誰から何kg仕入れるか」が分かる1つの仕入れ案を作るWebアプリです。

- 配分（どの農家から何kg）は通常のプログラムで計算します。AIは希望文の読み取りと、限定メニュー案の文章づくりだけに使います。
- 「仕入れ案」自体は注文でも在庫予約でもありません。画面には常に「未確保・農家承認前」と表示します。
- 飲食店が仕入れ案から実際に「仕入れ依頼」を送ると、農家が承認・辞退・条件変更で返答し、双方が合意して初めて「取引確定」になります（`api/orders.js`）。確定すると、その数量だけ本当に在庫（`listings`）から引かれ、二重に確約されません。
- 決済・配送手配の実処理は行いません。「確定」「配送完了」「受け取り確認」は状態の記録だけで、実際の送金や配送契約は対象外です。

## 構成

| パス | 役割 |
| --- | --- |
| `public/index.html` | 画面（飲食店・生産者の2役）。配分ロジックもここにあります |
| `public/manifest.json` `public/icon.svg` | ホーム画面に追加したときのアプリ名・アイコン（PWA） |
| `api/listings.js` | 出品・在庫の読み書き（全端末で共有。ログインした農家は自分の出品だけ、編集用パスコードはすべて変更できる） |
| `api/orders.js` | 仕入れ依頼の送信・承認・辞退・条件変更・取引確定・配送完了・受け取り確認（`lib/orders.js`が保存形式） |
| `api/auth.js` | 新規登録・ログイン・ログアウト・アカウント設定（農家名／店名・パスワードの変更） |
| `lib/auth.js` | パスワードのハッシュ化（scrypt）とログイン状態（Redisに有効期限30日で保存） |
| `api/parse.js` | 希望文をAI（Gemini）で項目に整理する |
| `lib/ai.js` | Gemini API を呼ぶ共通処理（REST） |
| `api/draft.js` | 仕入れ案の食材から、限定メニュー案（メニュー名・紹介文）をAIが書く |
| `lib/inventory.js` | 出品・在庫の読み込み（デモデータの日付繰り越しを含む） |
| `lib/domain.js` | 品目・地域・受渡場所のマスタ、デモデータ、入力検証 |
| `lib/store.js` | Upstash Redis への保存（未設定ならサーバーのメモリ） |
| `dev-server.mjs` | ローカル確認用サーバー（`node dev-server.mjs`） |

## 主な機能

- **希望条件の入力（飲食店）**：「明後日までに大阪近郊のトマトを10kg、多少形が悪くてもOK」のような自然文を、AIが品目・数量・希望日・地域・価格上限・規格外可否・受渡場所に整理。書かれていない条件は「指定なし」。確認画面で直してから確定する
- **仕入れ案**：条件の合う出品を、在庫上限・最低販売量・販売刻み・単位・受渡日時と場所を守って組み合わせる（通常のプログラムで計算）。条件をすべて満たす案のうち、仕入れ先が少ない → 合計価格が低い順。結果の最上部に数量・受け渡し・費用、農家別の配分と「確認が必要な点」、常に「未確保・農家承認前」を表示
- **不足・不一致の表示**：「希望10kgに対し8kg。2kg不足」「同じ日時・場所で受け取れる組み合わせがありません」「販売刻みの都合でちょうどにできません」を区別し、規格外可・地域・価格・場所・日付を変えた場合の成立案を示す（数量を勝手に丸めない）
- **在庫変更時の再計算**：在庫・公開状態が変わると、旧案を「使えない」と表示して残りの在庫で計算し直す（15秒ごとに確認）
- **販売できるものを登録（生産者）**：品目・品種・産地・区分（規格外の理由・余剰）→ 販売可能量・単位・最低販売量・販売刻み → 単価 → 受渡日・場所・時間 → 確認（飲食店からの見え方のプレビュー）。登録後は「数量を変更」「公開を止める」、出荷日の変更・編集・削除。同じ農家名を入れると前回の条件を読み込む
- **仕入れ依頼〜取引確定〜受け渡し**：仕入れ案が成立（デモ出品を含まない）したとき、ログイン中の飲食店が「仕入れ依頼を送る」と、農家ごとに依頼が届く。農家は承認・辞退・条件変更（数量・単価・日時）のいずれかで返答し、条件変更は飲食店が承諾するまで確定しない。承認・承諾の瞬間に、その数量だけ在庫から引かれる（同じ在庫が二重に確約されない）。確定後は、農家が「配送完了」、飲食店が「受け取り確認」を記録する。決済・実際の配送手配は行わない。辞退・取り下げになった依頼は、同じ条件で仕入れ案を作り直せる
- **記録**：送った仕入れ依頼の状況、保存した仕入れ案（注文・在庫予約ではない）。保存した案は開くたびにいまの在庫で計算し直し「同じ案で成立／在庫が変わりました」を表示
- **入力の下書き**：入力途中の希望・出品はこの端末に保存し、ホームから続きを再開できる
- **限定メニュー案**：仕入れ案の食材（規格外・余剰を含む）から、一般的な料理例・必要量の目安・原価の目安を表示。APIキーがあればAIがメニュー名・紹介文を作る
- **AI停止時**：APIキー未設定・上限・失敗のときは簡易読み取りで項目を埋め、手入力で同じ配分処理に進める
- **対象外の案内**：家庭用・全国配送は対応範囲を案内し、複数品目は最初の品目だけで続ける

書き込みの守り方：農家・飲食店はアカウントでログインします（新規登録には編集用パスコードが必要）。出品できるのは農家のアカウントで、変更・削除できるのは自分の出品だけです。編集用パスコード（管理者用）はすべての出品の変更とデモの復元に使います。ログイン機能より前に登録された出品とデモの出品は、管理者だけが変更できます。AIは在庫を読み書きしません。

仕入れ依頼は、ログインした飲食店アカウントだけが送れます（編集用パスコードでの代行はできません）。農家は自分あての依頼だけ、飲食店は自分が送った依頼だけを見られ、操作できます。デモの出品（実在のアカウントが無い）には依頼を送れません。

デモの出品（A農家5kg/600円・B農家3kg/550円・C農家2kg/350円 余剰・形の不揃い ほか）は架空のサンプルデータです。

## 画面

スマートフォンのアプリのように、下のタブで切り替えます。

| タブ | 内容 |
| --- | --- |
| ホーム | あいさつとサービスの流れ、入力の続き、いまの仕入れ案の状況、「仕入れ案を作る」「販売できるものを登録」の入口、公開中の出品数 |
| 仕入れ | 希望を入力 → 条件を確認 → 仕入れ案（3ステップ）。案は記録に保存でき、限定メニュー案も作れます。成立した案は（ログイン中の飲食店なら）「仕入れ依頼を送る」に進めます |
| 出品 | 受け取った仕入れ依頼（承認・辞退・条件変更）、出品・在庫の一覧と数量変更・公開停止。出品は 食材 → 数量 → 価格 → 受け渡し → 確認 の5ステップ（残りの必須項目数を表示） |
| 記録 | 送った仕入れ依頼の状況（条件変更の承諾・依頼の取り下げ・受け取り確認）、保存した仕入れ案。保存した案は開くたびに、いまの在庫で計算し直して「同じ案で成立／在庫が変わりました」を表示 |
| 設定 | ログインして使う設定（アカウント情報、農家名／店名・パスワードの変更、ログアウト）と、この端末の設定（編集用パスコード、保存する情報の説明、デモデータに戻す、この端末の記録を消す） |
| ログイン | ログイン・新規登録（農家／飲食店）。「ユーザー設定」ボタンから設定画面へ移動できる |

ビルドは不要です。Vercel が `public/` をそのまま配信し、`api/` をサーバー関数として動かします。

## 公開手順（Vercel）

パソコンに Node.js や git が入っていなくても、ブラウザだけで公開できます。

### 1. GitHub にアップロードする

1. GitHub で新しいリポジトリを作る（Private で構いません）。
2. 「uploading an existing file」から、このフォルダの中身（`api` `lib` `public` `package.json` `README.md` `.gitignore`）をまとめてドラッグして Commit する。

### 2. Vercel にデプロイする

1. https://vercel.com に GitHub アカウントでログインする。
2. 「Add New… → Project」で、1 のリポジトリを Import する。
3. Framework Preset は「Other」のまま、Build Command などは空欄のまま「Deploy」。

この時点で画面は開けますが、在庫の共有とAI読み取りはまだ動きません。

### 3. 在庫を共有するデータベースをつなぐ

1. Vercel のプロジェクト画面 →「Storage」→「Upstash for Redis」（Marketplace）を作成し、このプロジェクトに Connect する。
2. 環境変数 `KV_REST_API_URL` と `KV_REST_API_TOKEN` が自動で追加されます。

### 4. 環境変数を設定する

プロジェクトの「Settings → Environment Variables」に追加します。

| 名前 | 必須 | 内容 |
| --- | --- | --- |
| `GEMINI_API_KEY` | AI読み取りを使うなら必須 | https://aistudio.google.com で発行したAPIキー（無料枠で使えます） |
| `GEMINI_MODEL` | 任意 | 使うモデル。未設定なら `gemini-flash-latest` |
| `EDIT_PASSCODE` | 強く推奨 | 生産者画面で登録・数量変更・デモデータ復元をするときのパスコード。未設定だと、URLを知っている誰でも在庫を書き換えられます |
| `PARSE_LIMIT_PER_HOUR` | 任意 | AI読み取り・メニュー案の1時間あたり上限（接続元ごと）。既定は30回 |
| `DEMO_ROLLING_DATES` | 任意 | `0` にすると、デモデータの受渡日を毎日繰り越す処理を止めます |

設定後、「Deployments」から最新のデプロイを Redeploy すると反映されます。

### 5. 動作確認

1. 飲食店画面で例文「明後日までに大阪近郊のトマトを10kg、多少形が悪くてもOK」を選び、「AIで条件を整理する」→「仕入れ案を作る」。
   A農家5kg＋B農家3kg＋C農家2kg＝10kg、5,350円 と出れば正常です。
2. 別のスマートフォンで生産者画面を開き、パスコードを入れて C農家のトマトを1kgに変更する。
3. 1 の画面が15秒以内に「C農家が2kg→1kgに変更しました。現在の合計は9kgで1kg不足です」に変われば、在庫の共有と再計算が動いています。

## 注意

- AI読み取りは Gemini API の無料枠で動きます（回数の上限は Google AI Studio のプロジェクトごとに決まります。無料枠で送った内容は Google のサービス改善に使われることがあります）。1回の読み取りは短い入出力で、接続元ごとに回数の上限をかけています。
- APIキーが無い・上限に達した・AIが失敗した場合は、画面側の簡易読み取りに切り替わり、そのまま項目を直して先へ進めます。
- 仕入れ案と入力の下書きは各端末のブラウザに保存されます。出品・在庫・仕入れ依頼はデータベースで全端末共有です。
- 表示している農家・在庫・価格はすべて架空のデモデータです。デモの出品には実在のアカウントが無いため、仕入れ依頼は送れません（依頼には実際の農家アカウントの出品が必要です）。
- 「取引確定」は数量と条件の合意を記録するだけです。実際の代金の支払い・配送の手配はこのアプリでは行いません。
